Frequently asked questions

Answers to the most common questions about EvalAssist. Can't find what you need? Check the Docs page.

No. EvalAssist is a marking assistant, not a marking system. It suggests provisional scores based on TF-IDF similarity and keyword coverage, but every score must be reviewed and approved by a teacher before it is used. The teacher can edit any mark freely. The AI assists; the teacher decides.

For each criterion, EvalAssist computes two signals:

  • S – TF-IDF cosine similarity between the criterion and the answer (or the best-matching sentence)
  • K – share of the criterion's content words found in the answer

These are combined as: R = min(1, 0.65·S + 0.35·K)

Marks for that criterion = (maximum marks ÷ number of criteria) × R. The weights (0.65, 0.35) are a starting heuristic and are disclosed in full. See How it works for the full explanation.

EvalAssist accepts .txt, .pdf, and .docx files up to 8 MB. Files are processed locally; nothing is sent to an external server. PDF files must be text-based — scanned PDFs produce almost no extractable text, and OCR is not supported. The app will warn you if a PDF appears to be scanned.

No. EvalAssist stores nothing to disk and sends nothing to external servers. The session history visible on the Evaluate page exists only in your server's RAM and is cleared when the Flask server stops. Always use anonymised data — replace student names and IDs before uploading any file.

TF-IDF operates on word frequency, not meaning. A student who correctly explains a concept using different vocabulary from the rubric may score lower than expected. Similarly, keyword coverage checks for the presence of specific words, so correct paraphrases without the exact keyword are counted as missing. This is a known limitation — see Responsible AI for the full list. The teacher review step exists precisely to catch these cases.

Yes — always. Every suggested mark appears in an editable input field in the results table. You can change any mark at any time before approving. This is by design: EvalAssist's scores are starting points, not final decisions. Use the "Approve marks" button only after you are satisfied with every criterion's mark.

Yes. Once installed, EvalAssist runs entirely locally. It uses scikit-learn for TF-IDF (no API calls), and the web fonts (Poppins, IBM Plex Mono) are the only external resources. The scoring engine, file extraction, and all AI demos function without an internet connection. If Google Fonts are unavailable offline, the browser falls back to system fonts.

In Best-matching sentence mode (the default), EvalAssist splits the answer into sentences and computes TF-IDF cosine similarity between each sentence and the criterion. It uses the highest similarity score and shows the matching sentence in the evidence panel. This works well for long answers where a student addresses each criterion in a specific part of their text. Whole answer mode compares the entire answer at once, which can smooth out a short but highly relevant sentence.

Write each criterion as a complete, specific sentence that contains the key terms a student should use. For example: "Explain the time and space complexity of BFS with justification" works better than "complexity" alone. Each line in the rubric box becomes one scored criterion. The keyword-extraction step strips stop words and applies light stemming, so related word forms are usually matched.

Not without careful human review. EvalAssist is not validated for high-stakes assessment where marks determine progression, awards, or qualifications. The heuristic weights have not been tested against a dataset of human-marked answers. If you use it for any formal assessment, every provisional mark must be independently verified by a qualified teacher before release. See Responsible AI → When NOT to use it.
